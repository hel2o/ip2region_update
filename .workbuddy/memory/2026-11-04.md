## 新增 sync.sh / sync.bat：把 xdb 推到 99.26 的四个项目

目标机 192.168.99.26（root + ~/.ssh/es_deploy 免密，已写进 ~/.ssh/config，`ssh 192.168.99.26` 直接可用）。

四个目标：
1. `/home/work/management-system/xdb/ip2region.xdb`（线上运行目录）
2. `/home/work/workspace/src/github.com/hel2o/management-system/xdb/ip2region.xdb`
3. `/home/work/workspace/src/github.com/hel2o/sniffer/ip2region.xdb`
4. `/home/work/workspace/src/github.com/hel2o/english_school/ip2region.xdb`

设计要点：
- 先 scp 一份到 `/tmp/ip2region.<md5>.xdb`，再远端 cp 分发（4 次上传变 1 次）；同 md5 临时文件已存在则跳过上传。
- 目标 md5 == 源 md5 时报「最新」，不备份不覆盖（重复跑幂等）。
- 覆盖前 `cp -p` 备份成 `ip2region.xdb.bak.<YYYYmmddHHMMSS>`，每个目标只留最近 `-keep`（默认 3）份。
- 写同目录 `.tmp.<pid>` → `chown/chmod` 对齐旧文件 → `mv -f` 原子替换，避免服务读到半截文件。
- 远端脚本走 `ssh host bash -s -- args <<'REMOTE'`，绕开多层引号；输出用 `OK|SAME|BAD|路径|md5` 管道格式回传再渲染。
- 防呆：源文件 < 5MB 直接拒绝。不重启任何服务。

实测（2026-11-04 17:24）：management-system 两份已是同版本 → 跳过；sniffer 从 11,070,130 字节（2023-02-23 的老库）更新到 49,062,707，旧文件备份为 `ip2region.xdb.bak.20261104172400`；english_school 新建。四个目标回读 md5 全为 `f0e00c808c0185c4a7af9e4aff6e5943`，/tmp 临时文件已清理。

坑：sync.bat 里调 bash 必须先找 `%ProgramFiles%\Git\bin\bash.exe`，不能用 `where bash`（可能命中 WSL 的 C:\Windows\System32\bash.exe，路径语义不同）；另加 `chcp 65001` 免得中文输出乱码。

## 清洗重复层级（19:43~19:47）

用户反馈 "香港特别行政区香港特别行政区汇港电讯(WTTHK)" 这种重复。根因：`regions.Split`
对直辖市/特区把 City 回填成省级（`direct:true`），于是 省==市 完全重复。

量化（txt 8 列）：市==省 115,546 段（中国 96,661：上海 45,089 / 北京 21,312 / 天津 19,702 /
香港 6,798 / 重庆 3,688 / 澳门 72；境外 18,885，如 美国|哥伦比亚特区、俄罗斯|莫斯科）；
区==市 23,466 段（洛杉矶市/县这类）；区==省 仅 6 段。

规则（写进 `cleanGeo`）：**同名时清掉"市"**，省（最粗）和区县（最细）都保留：
- 市 == 省 → 清市（直辖市/特区）
- 市 == 区 → 清市（洛杉矶、东莞不设区）
- 区 == 省 → 清区（汉堡三层同名）
单测 `cmd/ip2region/sanitize_test.go` 覆盖 8 个用例（含"吉林省吉林市不算重复"的反例）。

实测一次清洗 149,996 段；重复层级残留归零；段数 2,798,292 → 2,798,082。
已 merge+build+sync（md5 582801ba...），四个目标一致。

遗留可选项：港澳台 16,102 段里 8,361 段 ISP 为空、5,531 段运营商名被塞进"镇"字段
（parse 规则：中国 IP 的非运营商 area 并入镇）。要更准的话应在 parse 阶段把港澳台
单独当作"境外"处理，让运营商名进 ISP。

## 全量重建是否自动去重（19:50）

结论：会。`all` 链路 `... → merge → build -from txt`，`merge` 是成品 txt 唯一出口，
`sanitizeSegments` 挂在那里，`build -from txt` 直接吃 merge 产物，所以全量跑完必然去重。

同轮加固：
- `merge` 出口硬断言：Compact 后 `countWatermarks` / `countDuplicateLevels` 任一 >0 直接
  return error，脏数据落不了库。
- `verify` 统计的是 SQLite **中间表**，那里 `省==市` 是设计状态（直辖市/特区，enrich
  用 geoLevel 比层级时需要），所以只打印"段表同名层级 N 段"不告警。曾短暂写成 `!!` 告警，
  verify 报 149,997 段属于误报，已改回中性提示。
- 注意 `build -from db` 会自己 sanitize；`build -from txt` 不 sanitize（信任 merge）。
  手工改 txt 再 build 的话脏值不拦，要走一次 merge。

## 探测百度 qifu IP 画像接口的鉴权与限流（19:47~20:10）

接口：`GET https://qifu.baidu.com/api/v1/ip-portrait/brief-info?ip=x.x.x.x`
返回：country/province/city/isp/scene/company/risk_score/hit_risk_num/security_risks（5 类风险标签），支持 IPv4 与 IPv6。

**关键结论：Acs-Token 和 Cookie 都不是必需的**（用户给的 curl 里那个 token 已过期，仍能用）。
唯一硬门槛是 WAF 两个头：
- UA 必须是浏览器 UA（`curl/8.0` → 403 Forbidden openresty）
- Referer 必须是 `qifu.baidu.com` 域（含子路径都行；无 Referer 或 google 域 → 403）

限流实测（全部 code=200，无一例 429/403/业务错误码）：
- 20 并发 200 次 → 72 QPS
- 50 并发 1000 次 → 176 QPS
- 10 并发 2000 次持续 45s → 44 QPS，零失败
- 100 并发 3000 次 → 108 QPS，2989 成功 + 11 个 20s 超时（直连，非本地代理瓶颈）
- 累计约 6600 次请求未触发封 IP / 配额
- 响应头无任何 RateLimit 字段；同 IP 连查 traceId 每次不同 → 无缓存，每次真查

边界行为：非法 IP（如 `abc`）返回 code=200 但 data 全 null；内网 IP 返回 scene="私有地址"。
探测脚本留在 `.workbuddy/tmp/`（`hit.sh` 单发、`loadtest/main.go` Go 压测器，参数=并发 总量）。

## all 新增 -only-custom（20:00）

用户问"只加载自定义内容怎么跑"。此前 `all` 没有该模式，`rebuild.bat` 虽转发参数但一定跑 parse
（重灌段表 = 洗掉百度/GeoCN 增强）。

实现：`-only-custom` 强制 `skipFetch/skipLegacy/skipEnrich/skipRefine=true`，跳过 parse，
只跑 merge + build；verify/stats 也跳过（读的是 SQLite 段表，段表没动等于重复报旧数字）。
实测 `all -only-custom` 32 秒 / 输出 2,798,082 段 / 覆盖 4294967296 / 59.2MB。

用法：`rebuild.bat -only-custom` 或 `./rebuild.sh -only-custom`，再 `sync.bat` 推服务器。
等价手工：`merge` + `build -from txt`（别用 build -from db，那条会重导出但不叠自定义）。

顺带清理：`.workbuddy/tmp` 之前被 `git add -A` 带进仓库（含 ~10MB exe），已 `git rm --cached`
并加进 .gitignore；`.workbuddy/memory` 仍跟踪。
